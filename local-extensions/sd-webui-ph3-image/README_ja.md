# P-H3 Image Native for Forge Neo

> **2026-11-05 Windowsローカル修正・実機検証追記:** このPCのForge Neo / RTX 4070 Ti SUPER 16GBで2048×2048の実生成2回、停止、エラー後の解放、通常Anima生成への復帰を確認しました。直接原因・条件・計測値・未検証範囲は [Windows検証記録](docs/VALIDATION_WINDOWS.md) を参照してください。以下の0.1.0配布時点の説明・未検証表記は履歴として保持しています。

**0.1.0-experimental / 2026-11-05**

Forge Neo / EasyForgeNeoに「P-H3 Image」専用タブを追加する、文章からの画像生成向け拡張です。ComfyUIをインストール・起動したり、別のComfyUIサーバーへ処理を送ったりしません。

> **検証状況**
> この拡張による、実モデルを使用したGPU画像生成は未検証です。RTX 4070 Ti SUPER 16GB + RAM 64GBでの成功・所要時間・出力品質は保証していません。CPUテストの成功を、GPU動作確認の代わりにはしていません。既存環境を自動更新しない構成ですが、最初は普段のForge環境のコピーで試してください。
>
> 実装されているのは文章からの画像生成です。画像編集、参照画像、Prompt Upsampler、LoRA、XYZ比較、通常のtxt2img / img2imgへの統合は含まれません。

## 1. 導入

### 1-1. 拡張フォルダーを配置

Forge Neoを終了し、ZIP内の `sd-webui-ph3-image` フォルダーを、**Forge本体の `extensions` 直下**に置きます。EasyForgeNeoのランチャーの隣ではなく、実際のWebUI本体のフォルダーです。

```text
Forge Neo本体/
  extensions/
    sd-webui-ph3-image/
      scripts/
        ph3_image.py
      ph3_native/
      tools/
      setup_native.bat
      download_models.bat
      README_ja.md
```

フォルダーが二重になって `extensions/sd-webui-ph3-image/sd-webui-ph3-image/scripts/` とならないようにしてください。

### 1-2. ネイティブ推論ソースとトークナイザーを準備

`setup_native.bat` を実行します。必要なのはインターネット接続です。この処理で行うのは次の準備だけです。

| 取得するもの | 保存場所 | 内容 |
|---|---|---|
| コミット固定のMiniMax-H3ネイティブ実装 | `_vendor/h3/` | Forge向けの推論クラス。上流拡張のWebUI登録スクリプトは取り込みません |
| P-H3公式のトークナイザー | `tokenizer/` | 文章をトークンに変換する小さな設定・辞書ファイル。取得時のリビジョンを記録します |

**モデル重みのダウンロード、pip install、Torchの差し替え、Forgeのgit pull、ComfyUIの導入は行いません。** 本拡張の `install.py` も依存ライブラリを自動変更しません。

BATは一般的なForgeのPython配置を探します。Pythonが見つからない場合や別のPythonが選ばれる場合は、Forgeを動かしているPythonを指定して実行してください。

```bat
"ForgeのPython.exeの実際のパス" tools\setup_native.py
```

この段階で失敗した場合は、続けて生成せず、コンソールのエラーを確認してください。既存ファイルを強制的に置換する修復は、自分で `--repair` を指定したときだけ行います。

### 1-3. モデルを用意

推奨の開始構成は、公式 `PrunaAI/P-H3-Image-Comfy` の次の3ファイルです。[1]

| 用途 | ファイル名 |
|---|---|
| 生成モデル | `diffusion_models/p-h3-image_w4a8.safetensors` |
| 文章エンコーダー | `text_encoders/p-h3-image_text_encoder_int8_convrot.safetensors` |
| 静止画VAE | `vae/p-h3-image_vae_int8_convrot.safetensors` |

すでに保存してある場合は、**そのままファイルパスを指定して再利用**できます。ComfyUIのモデルフォルダーに保存してあるファイルも、ComfyUI自体を起動せず読み込みます。モデル名に「Comfy」と付いているのは、この場合は重みの配布形式を指します。

未取得の場合は `download_models.bat` を実行します。利用条件を自分で確認して `AGREE` と入力した後、上の3ファイルと利用条件等の小さな文書だけを取得します。既定の構成は**約22GBのディスク容量**を使います。これはVRAM使用量ではありません。Prompt Upsamplerは取得しません。

ダウンロード先は原則として次です。

```text
Forge Neo本体/models/P-H3-Image/
```

スクリプトはモデル取得時点のリビジョンを固定し、`ph3_download_receipt.json` に記録します。配布ファイル名が変わっていた場合は、別ファイルを推測して取得せず停止します。初回のオンライン取得とWindows上でのBAT実行自体は、この配布物を作成した環境では実施していません。

### 1-4. WebUIから診断

Forge Neoを起動し、「P-H3 Image」タブを開きます。3つのファイルパスを確認して、**「環境・モデルの診断」**を押してください。

診断では、Forgeの必要なAPI、CUDAデバイス、VRAMモード、推論ソースのチェックサム、モデルのヘッダー等を確認します。`api_and_headers_ok: true` は、**画像生成成功を意味しません**。また、ヘッダー検査はファイルの出所を証明するものではありません。公式のP-H3単体モデルを選んでください。

通常のMiniMax-H3本体＋蒸留LoRA、H3用32B文章エンコーダー、H3動画VAEを、この3ファイルの代わりに選ばないでください。

### 1-5. 最初の生成

初期値は **2048×2048 / 1枚 / 8ステップ / 作業用VRAM目安6GiB / VAEタイル256** です。まずはこの設定で1枚を試します。プロンプトは、画像の種類・主役・背景・光・構図を具体的な文章で入力してください。

公式は文章からの生成に約8MP、正方形なら2912×2912を推奨しています。[2] 本拡張の2048設定は初回の動作確認用であり、画質面の推奨値を置き換えるものではありません。動作を確認した後に、2912×2912等へ手動で変更してください。解像度を勝手に下げる動作はありません。

生成画像は、Forgeの `outdir_samples`、未指定なら `outdir_txt2img_samples` の下の次のフォルダーに保存します。

```text
設定済みの出力フォルダー/p-h3-image/YYYY-MM-DD/
```

PNGにはA1111系の `parameters` メタデータ、同名のJSONには実行条件を保存します。Google Drive等への保存機能はありませんが、**Forge側の出力先をクラウド同期フォルダーにしてある場合は、その設定に従います**。

## 2. メモリ管理の仕組み

本拡張では、Forge Neoにある量子化演算と `ModelPatcher` / `memory_management.load_models_gpu()` を利用します。[3] 独自に全モデルを `.to("cuda")` して同時常駐させる方式ではありません。

```text
Forgeの共有生成ロックを取得
  → 前のGPUモデルを退避
  → 文章エンコーダーを必要な範囲でGPUへ読み込み
  → 文章埋め込みをCPUへ保存し、文章エンコーダーをGPUから退避
  → 生成モデルを必要な範囲でGPUへ読み込み
  → 8ステップで潜在画像を生成
  → 潜在画像をCPUへ移し、生成モデルをGPUから退避
  → 静止画VAEを読み込み、タイル単位で復元
  → PNG / JSONを保存
  → GPUモデルを退避し、生成ロックを解放
```

| 対策 | 実装内容と注意点 |
|---|---|
| 量子化 | 公式のW4A8 / INT8形式をForgeの既存演算でロードする経路を実装。実際のGPUカーネル動作は未検証です |
| 部分読み込み | Forgeの管理に重みの常駐量を判断させ、入りきらない重みをCPU側へ残します |
| 処理段階ごとの入れ替え | 文章処理・画像生成・VAEの切替で前段のGPUモデルを退避します |
| CPUメモリ | safetensorsのmmap参照と、上流のfile-backed復帰処理を利用します。変換された重み等はすべてがmmapのままとは限りません |
| キャッシュ | 同一モデルと同一プロンプトの埋め込みをCPU側に保持できます。無効にした場合は生成終了時に破棄します |
| 不要な部品を省略 | この文章生成専用版では、未使用の画像認識部、VAEエンコーダー、音声VAE、Prompt Upsamplerを構築しません |
| VAEタイル | 128 / 256 / 512ピクセルを選択でき、復元時のタイル同時処理は1に固定します |
| 同時実行防止 | Forge本体と同じ生成ロックを使い、通常のGPU生成と重ならないようにします。他拡張がロックを無視する場合までは制御できません |
| 停止 | 文章処理の層、画像生成の層・ステップ、VAEタイル等の境界で停止します。実行中のCUDA演算を即座に強制終了するものではありません |
| VRAM不足 | 同じSeed・同じ解像度を保ち、作業用メモリ目安を増やし、VAEタイルを縮小して1回だけ再試行します |
| 後始末 | 正常終了・例外・停止時にGPUモデルを退避します。解放処理自体の失敗はログに残し、完了扱いにしません |

**ComfyUIのDynamicVRAMそのものを移植したわけではありません。** 必要な重みだけをGPUに載せ、CPUへ退避し、処理段階ごとに使い分ける方針です。ComfyUIと完全に同じメモリ消費、生成時間、同一Seedの画素結果は保証しません。

また、「作業用VRAM目安6GiB」はGPU使用量を10GiB以下に制限する設定ではありません。実際の空き容量やForgeの判断、途中の作業領域によって変わります。CUDAコンテキスト等が残るため、モデル退避後にタスクマネージャーのGPUメモリが0になることも保証しません。

`comfy-kitchen` という名前の演算ライブラリをForge経由で使いますが、これはComfyUIのWebサーバーやノード実行エンジンを起動するという意味ではありません。

## 3. 入力と生成条件

8ステップとP-H3の専用シグマ列を固定しています。[2]

```text
1.0, 0.984753, 0.967905, 0.951688, 0.925372,
0.881923, 0.810083, 0.528718, 0.0
```

CFGの追加パス、ネガティブプロンプト、任意のサンプラー選択はありません。静止画生成であってもモデル内部が必要とする音声潜在ストリームは処理し、音声ファイルへの復元だけを省略します。

幅と高さは32の倍数、256〜4096、合計900万画素以下です。極端に小さい解像度が良い画像になると保証するものではありません。同時バッチは1で、連続枚数は1〜16です。Seedは1枚ごとに1ずつ増えます。`-1` は開始Seedをランダムに選びます。

入力プロンプトをそのまま使用します。`(word:1.2)`、`<lora:...>`、styles、Dynamic Prompts等のWebUI構文は解釈しません。トークン上限を超えた場合は、黙って切り詰めずエラーにします。Prompt Upsamplerがないため、必要な情景は自分で具体的に記述してください。

## 4. 問題が出たとき

| 症状 | 確認すること |
|---|---|
| 専用タブがない | フォルダーの二重化、拡張の無効化設定、起動コンソールのImportErrorを確認してください |
| ネイティブ推論ライブラリが未設定 | Forgeを終了し、`setup_native.bat` の完了を確認してください |
| 必要なForge APIがない | A1111本家・旧ForgeではなくForge Neoか確認してください。改変環境を無断で最新版に上書きしないでください |
| 量子化形式に未対応 / カーネルがない | Forge、Torch、CUDAビルド、comfy-kitchenの組み合わせを診断ログで確認します。本拡張は自動で入れ替えません |
| HIGH_VRAM / GPU_ONLYで停止 | CPU退避を無効にする起動設定では実行しません。通常のオフロード可能な設定で起動してください |
| safetensorsのキー不足・余剰 | 別モデルや別VAEを選んでいないか確認します。公式ファイルでも起きる場合は、この移植コードと実際の形式の不一致の可能性があります |
| CUDA OOM | 他のGPUアプリを終了し、ログにある失敗段階を確認します。自動再試行も失敗した場合は手動で解像度等を変更してください |
| 解放処理の例外 | 次の生成を続けず、ログを保存してForgeを終了・再起動してください |
| 出力がおかしい | 成功表示だけで正常画質とは判定できません。PNG、JSON、実行ログを保存し、同じモデルの参照実装との比較が必要です |

ログは拡張内の `logs/` に保存します。診断ボタンのJSONと、生成時のJSONLの両方を出力できます。共有前に、ローカルのフォルダーパスやプロンプト等、見せたくない情報が含まれていないか確認してください。

手動の「GPU・CPUキャッシュを解放」はForgeが別の生成をしている間には実行しません。次の通常生成では、Forgeが通常モデルを必要に応じて再ロードします。

## 5. 検証済み範囲と未検証範囲

`docs/VALIDATION.md` に検証環境と結果を記録しています。CPU上の小型テンソル計算、入力検証、シグマ列、PNG保存、停止・OOM・ロックの模擬テスト等と、**実際の大規模モデルの生成テストは別物**です。

未検証なのは、少なくとも以下です。

- 公式の実重み3ファイルの全ロードからPNG出力までの通し動作。
- Windows版Forge Neo / EasyForgeNeoの実プロセス内での互換性。
- RTX 4070 Ti SUPER 16GBでの生成成功、実VRAM / RAMピーク、所要時間。
- CUDA量子化カーネル、NaNの発生有無、VAEタイル境界、参照実装との画質・数値比較。
- オンラインの初回セットアップ、長時間連続生成、他拡張との併用。

このため、実機の結果に応じて修正が必要になる可能性があります。

## 6. 無効化・削除

Forgeの拡張一覧で無効化して再起動するか、Forgeを終了して、この拡張フォルダーを `extensions` の外へ移動してください。`extensions` 内で単に名前を変えるだけでは、再び読み込まれる場合があります。

モデルファイル・生成画像は別の保存場所に残ります。本拡張には、それらを一括削除する機能はありません。Forge本体のコード、依存ライブラリ、styles.csv、既存ワークフローを復元する作業は不要です。本拡張はそれらを書き換えません。

## 7. 開発・引き継ぎ

`docs/IMPLEMENTATION.md` にファイルの役割と、実機での受け入れ確認項目を記載しています。CPUテストは開発用環境で次のコマンドを実行します。普段のForge環境へpytest等を勝手に追加する必要はありません。

```text
python -m pytest -q
```

拡張コードのライセンスはAGPL-3.0-or-laterです。上流コードとモデルの条件はそれぞれ別に適用されます。`NOTICE` と取得元の利用条件を確認してください。モデル重みはこのZIPに含まれていません。
